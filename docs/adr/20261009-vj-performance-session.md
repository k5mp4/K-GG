# ADR-20261009-vj-performance-session: VJ演奏の時計と設定をPresetから分離する

## コンテキスト

通常エディターを維持しながら270px程度の高さで演奏する必要がある。既存のTimelineはアニメーション用で、再生・停止、Preset読み込み、duration変更が演奏リストの切替間隔へ影響してはならない。Presetに演奏環境を保存すると、持ち運ぶ映像データと端末ごとのUI設定が混ざる。

現行契約は[VJ Performance](../specs/current/vj-performance.md)、[Workspace Layout](../specs/current/workspace-layout.md)、[Preset System](../specs/current/preset-system.md)を参照する。related_specsはLegacy SPEC用のため空とする。

## 決定

VJ設定をアプリ設定として保存し、Preset形式へフィールドを追加しない。4拍の切替には単調増加時刻を使う独立時計と、次候補を保持する演奏キューを用いる。遅れた区間は1回に集約する。

通常・VJで同じ描画canvasとPreset適用処理を使う。既存のdocument actionsを一時stateへ実行し、正規化がすべて成功してから一度だけlive storeへ反映する。壊れた入れ子データで途中の映像だけが残ることを防ぐ。VJ読み込みでは適用結果のresolutionを受け取っても出力サイズへ反映しない。Shader準備も現在のコンテキストで行う。

切替の準備と適用を分離する。演奏対象全件のCPU正規化・cloneとShaderのprefetchを先に完了し、切替はGPU待ちを含まない同期処理とする。全件が使うNoise variantを有限の対象集合として既存contextへ保持し、VJ退出で解放する。GPU contextが変わった場合は準備状態を無効にする。旧Presetの省略値と現在のPreview Loopの引継ぎは同期反映時に解決し、未準備のモードを引き継ぐ場合は先に再準備する。

演奏中は通常のバックグラウンドShader準備を停止し、演奏対象に含まれないコンパイルの負荷を避ける。現在描画のdemandと演奏対象のprefetchは維持し、退出後は通常準備を再開する。失効したcontextのコンパイル中断をShader失敗や準備完了と扱わない。

演奏対象にはカスタムリストのほか、K-GG保存済みライブラリのルート／フォルダを指定できる。フォルダIDと子孫包含をアプリ設定へ保存し、ライブラリの保存順を既存巡回キューへ渡す。OSフォルダ読み込みやPreset形式変更は行わない。非表示の通常編集パネルはReact Activityで状態を維持し、演奏中の購読・Effectを停止する。canvasは同じ位置で描画を継続する。

ランダム化は正規のパラメータ制限から作るscalarカタログを使い、変更したパラメータだけをstatic trackへ切り替える。キーフレームを削除せず、演奏セッションの一時snapshotから復帰できる。エフェクト順序の既存Randomizeは別機能として維持する。

4拍ごとの自動読み込みには、次の元Presetへ範囲内ランダムを適用した一時ドキュメントを準備する。全件の元Presetキャッシュと次の1件のキャッシュを分け、元のマップを再cloneせず共有し、準備中に映像を変更しない。巡回ごとに新しくランダム化し、未準備の候補を拍境界で適用しない。手動読み込みは元のPresetを保つ。

## 理由

プリセット変更やTimeline停止で演奏時計をリセットしないため、演奏のテンポを保てる。既存描画・保存境界を共有し、UI縮小によるWebGL再生成や出力寸法変更を防げる。制限の正本を共有し、完全ランダムでも不正なenumや範囲外値を作らない。

## 代替案

| 案 | 採用しなかった理由 |
| --- | --- |
| Timelineのdurationを切替時計として使う | 既存アニメーション設定・Presetの影響で演奏の間隔が変わる |
| 別のプレビューcanvasをVJ用に作る | GPUコンテキスト、外部出力、描画状態の同期が増える |
| VJ設定をPresetへ含める | 保存形式を変え、端末設定と映像ドキュメントを混在させる |
| すべてのアニメーションを停止する | 操作していないパラメータの動きまで失う |

## 結果

### 利点

- 通常エディターとPresetの互換性を保ちながら、VJの時計と復帰操作を追加できる。

### 欠点・コスト

- Effect固有のモード依存条件はカタログで管理し、新しいscalar項目には追従が必要。
- 演奏開始前の全件準備に時間がかかり、通常のNoiseキャッシュよりメモリを使う。件数を表示し、準備済み候補は手動で使える。全件完了まで自動開始を抑止する。
- MIDI clock、音声からのBPM検出、プリセット間のGPUクロスフェードは今回含めない。

## 再検討条件

外部クロック同期、演奏リストのファイル共有、プリセット間補間が要求されたとき。実機でキーフレーム復帰やShader準備が演奏を阻害する場合も再検討する。設計要件は直接依頼で合意済みだが、このADRのaccepted化はリポジトリのレビューで判断する。
