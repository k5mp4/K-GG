# ADR-20260930-sandbox-shapes-final-stage: SANDBOX ShapesをSVGアルファで描画全体を後段合成する最終段として扱う

## コンテキスト

K-GGで作った描画を、ロゴ・文字のアウトライン・アイコンなど任意のSVG形状へ割り当て、「動くストライプ＋グレイン感のあるオーラ」で光らせ、表示・非表示をループさせたい要求があった。利用者はK-GGの描画を形状に割り当てたときにどのようなグラフィックになるかを試したい。最初の実装（K-GGの描画をハードライトで陰影付けし、ストライプを重ねる）はイメージと違うとの判断を受け、インナーシャドウでなめらかに縁取り、内部のFillを動かし、その輝度をグラデーションへ反映する、サーモグラフィやdepthパスのような連続的なグラデーションを目標にした。元になった要求はSVGフィルター（`feGaussianBlur`、`feComponentTransfer`、`feTurbulence`など）での実装だったが、K-GGの描画はWebGL2で生成され、Preview、Thumbnail、静止画、連番、動画、タイル書き出しで同じ結果を出す契約がある。

決めるべき事項は次のとおり。

- パイプライン上の位置。形状はK-GGの描画「全体」を受け取るべきで、Main Stackの途中に置くと後段（Prism、Flow、Particles、Seamless）が形状の外まで描いてしまう。
- 描画手段。SVGフィルターはDOM上の表示には向くが、WebGLの書き出し経路（Tauri動画、タイル）へ通らず、Safariの`feImage`やフィルター領域の制約もある。
- 入力SVGの扱い。任意のSVGは色、線、不透明度、フィルター、スクリプトを含みうる。
- 保存規則。Portableなプリセットは外部入力を保存しない（PRESET-002）。
- 表示・非表示ループの時刻。ループの端で切れ目が出ると動画素材として使えない。

## 決定

1. ShapesはSANDBOXの固定段で、全体の最終段とする。`renderFrame`が既存の`render`を呼んだ後に`renderShapesPass`を呼び、描画面の内容を専用textureへ`copyTexSubImage2D`でコピーしてから、同じ描画面へ描き直す。`render`内部の各経路（Legacy／V2、Direct／Core／Full、Cloth Base、Seamless）へ分岐を追加しない。
2. 描画はGLSL ES 3.00の専用program（`shapes`）1つで行う。遅延コンパイルし、有効時だけExport準備で待つ。パラメータ値ごとにprogramを作らない。
3. 形状はアルファだけを使う。SVGはマスクcanvasへラスタライズし、mipmap付きtextureとして使う。ぼかし（インナーシャドウ、本体、オーラ）はmipmapを前置フィルタにした25点のリングカーネルで近似し、半径によらず一定コストとする。長さはすべて形状の短辺に対する比で指定し、SVGの単位やCanvas解像度に依存させない（文字の細い線でも内部の奥行きが作れる）。
4. 内蔵形状（円・星・文字のアウトライン）はパスデータとして持ち、`Path2D`で同期的にラスタライズする。利用者のSVGはDOMParserで解析・無害化し、アルファを下げる属性とスタイルを取り除き、画像としてデコードする（スクリプトを実行せず外部資源を読まない）。
5. 出力は画素ごとの0..1の輝度の場とし、Gradient Rampで着色する。場は「なめらかな輪郭 → 3スケールのぼかし平均によるインナーシャドウの奥行き → 動くFill（ループするノイズ、奥行きの帯、ストライプ、K-GGの描画の輝度）→ 外側へ続くオーラ」で作り、縁で段差や平坦部ができないよう、オーラと内部を加重和してソフトニーで1へ収める。K-GGの描画はFillの輝度として使い、固定の配色プリセットを持たない。
6. 読み込んだSVGはセッション内だけで保持し（`shapesMaskStore`）、Presetには`source: custom`と見た目の設定だけを保存する。SVGがない場合は内蔵の星で描画する。
7. 表示・非表示とFillの動きの時刻はLoop Timing適用後のループ位相を使い、サイクル数とFillの周期を整数に限定し（ノイズは標本点を円周上で1周させる）、正規化時刻0と1を一致させる。各サイクルは表示状態から始める。AnimationがOFFのときは常に表示する。
8. 画素座標はグローバル座標（`gl_FragCoord + tileOffset`）から求め、タイル書き出しをフル描画と一致させる。

## 理由

- 最終段にすると、形状は「完成したK-GGの画」を受け取るという利用者の意図どおりになり、既存の各経路の描画契約と分岐を変更せずに済む。コピー1回とフルスクリーン1パスの追加で済む。
- WebGLで実装すれば、Preview、Thumbnail、静止画、連番、Browser／Tauri動画、タイルが同じshaderを通る。SVGフィルターではこれらの経路に載らない。
- mipmapによるぼかしは、ガウシアンの分離パスや追加FBOを持たずに任意半径を扱え、表示・非表示でオーラ半径を毎フレーム変えても負荷が一定である。
- 形状をアルファだけに正規化すると、入力SVGの色やスタイルに関係なく同じ見た目を別の形状へ適用できる。
- 内蔵形状をパスデータにすると、Thumbnailと書き出しで非同期の画像読み込みを待たずに再現できる。
- SVGを保存しない規則は既存のTexture画像・Image Gradient Sourceと同じで、Presetの移植性とサイズを保つ。

## 代替案

| 案 | 採用しなかった理由 |
| --- | --- |
| SVGフィルター（`feGaussianBlur`／`feComponentTransfer`／`feTurbulence`）でDOM上に重ねる | 元の要求の実装方針だが、WebGLの書き出し経路・タイルに載らず、PreviewとExportの一致契約を満たせない。Safariの`feImage`・フィルター領域の制約もある。 |
| Main Stackの通常レイヤーにする | 形状の後ろにPrism、Flow、Particles、Seamlessが描かれて形状の外へはみ出し、「画を形状に割り当てる」意図にならない。並べ替え可能にする利点も小さい。 |
| `render`内部の各経路の末尾へShapesパスを追加する | Legacy／V2、Direct／Core／Full、Cloth、Seamless、タイルの各分岐に同じ処理を足す必要があり、既存経路の契約を変えるリスクが大きい。 |
| 分離ガウシアン（H／V 2パス）でぼかす | 半径を毎フレーム変える表示・非表示ループで、ぼかし用のFBOと複数パスが必要になる。mipmap近似で見た目の要求を満たせる。 |
| 読み込んだSVGのマークアップをPresetへ保存する | Presetの共有で形状も再現できるが、外部入力を保存しない既存規則と異なり、サイズ上限・無害化の保証範囲を保存形式として決める必要がある。再検討条件とする。 |

## 結果

### 利点

- 任意のSVGを差し替えるだけで、同じ輪郭・奥行き・Fill・オーラ・グレインを別の形状へ適用できる。
- 着色がGradient Rampに統一され、Rampを編集するだけでサーモグラフィ、depth、任意の配色へ切り替えられる。K-GGの描画はFillの輝度として形状内部を動かせる。
- 表示・非表示ループとFillの動きがAnimationのループ端で一致し、動画素材として使える。
- タイル書き出しがフル描画と一致する（検証でタイル512pxと単一描画の差が0）。

### 欠点・コスト

- Shapes有効時は、描画面のコピーと、1画素あたり最大約125回のmask参照と約27回の3Dノイズ評価を行うフルスクリーン1パスが増える（実GPUでの時間は未測定）。
- マスクは長辺2048pxなので、4K以上で形状を大きく表示すると輪郭がわずかに柔らかくなる。
- ぼかしはガウシアンの近似で、厳密なSVGフィルターの`stdDeviation`とは一致しない。
- 読み込んだSVGはPresetへ保存されず、共有したPresetでは星へ戻る。
- 塗りを持つ背景矩形を含むSVGは、その矩形も形状になる（アルファだけを使うため）。
- MCPの制御対象・スナップショットには`shapes`をまだ含めない。

## 再検討条件

- SVGマークアップや画像素材をPresetへ含める保存形式（アーカイブ形式）が決まった場合。
- 実GPUでShapes有効時のPreviewが目標フレームレートを保てない場合、または8K書き出しで輪郭の解像度が不足する場合。
- 形状を複数重ねる、形状ごとに異なる設定を持つなどの要求が出た場合。
