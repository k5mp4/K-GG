# ADR-20260929-sandbox-texture-material-stage: Textureを高さ場と異方性反射のEffect Stackレイヤーとして扱う

## コンテキスト

CDの盤面の異方性反射と虹色の回折、ヘアライン加工の金属、紙の繊維といった質感を、Effect Stackで作った画像へ後から重ねたい要求があった。素材は手続き型のプリセットと任意の画像の両方で指定できる。当初はSANDBOXの固定段（Main Stackの後・Prismの前）として実装したが、実際に使った利用者から、質感を他の効果と同じように並べ替えたい要望があり、並べ替え可能なEffect Stackレイヤーへ変更した。

既存の効果ではこの質感を作れない。Normalは輝度から法線を作るだけでライティングをしない。GlassTileやNoiseは画像を歪めるが、ライトに応じて動くハイライトを持たない。異方性の見た目は、ライトの位置と表面の向き（グレイン）が画素ごとに変わることで初めて成立するため、共通の色変換では表現できない。

決めるべき事項は次のとおり。

- パイプライン上の位置。質感より後ろの効果が歪めると光沢が壊れる一方、質感の下でノイズやガラスを重ねる構成や、質感の上へ別の効果を重ねる構成は、どちらも表現として成立する。位置は利用者が選べるほうがよい。
- 高さ場と接線（グレイン方向）をどう表すか。
- 外部画像の保存規則。Portableなプリセットは外部画像を保存しない（Preset Systemの既存規則）。
- タイル書き出しとの整合。フル描画とタイル描画で結果がずれると、大きな解像度の書き出しだけ質感が壊れる。

## 決定

1. TextureはEffect Stackの通常レイヤー（`EffectStackKind`の`texture`）とし、配置された位置の前段textureを入力に取って後段へ出力する。drag、randomize、solo、選択、永続化、render planの対象にし、有効状態と順序は`effectPipeline.effectStack`、設定は`texture`へ保存する。既定順は最後（`Cone`の後）で、既定は無効。設定はPostprocessの`Edit Layer`で編集し、SANDBOXには置かない。
2. 高さ場`h(p)`を素材の一次表現とする。手続き型プリセットは関数として、画像は輝度として同じ`heightAt`から供給し、法線は`h`の差分から求める。接線（グレイン方向）は一様な`rotation`方向と、中心まわりの接線方向（`spunMetal`／`cdGroove`）から選ぶ。
3. 反射は点光源に対するWard異方性反射とし、`roughness`と`anisotropy`で接線・従接線方向の粗さを決める。CD風の虹色は、ライトの面内成分を溝直交方向へ射影した値から`spectrum`を引いて加算する（回折格子の式の近似）。
4. 画素座標はグローバル座標（`gl_FragCoord + u_tileOffset`）とフル解像度の高さから求め、模様の周波数はキャンバスの高さに対する相対値にする。これにより解像度とタイル分割に依存しない。
5. 読み込んだ画像はセッション内だけで保持し、Preset、Thumbnail、書き出しの設定へ保存しない。画像が未読込のときは、選択中の手続き型プリセットで描画する。
6. 専用program（`texture`）を1つ追加し、Textureレイヤーが有効なときだけ遅延コンパイルする。パラメータ値ごとにprogramを作らず、値はuniformで渡す。Effect Stack V2だけで動作する。Image Gradient Sourceの保護中も、画像を再サンプルしない照明なのでレイヤーを適用する。
7. ライトの回転（`lightSweep`）は整数回転とし、正規化時刻に比例させてAnimationのループに合わせる。

## 理由

- レイヤーにすると、質感をNoiseの後に置いて「ノイズで作った色の変化をそのまま金属の色にする」ことも、Noiseの前に置いて「質感の筋をノイズで歪める」ことも、同じ操作で選べる。実際の描画で、順序によって見た目が大きく変わることを確認した。
- 既存のレイヤーと同じ選択、ON／OFF、drag、randomize、soloが使え、Datamoshと同じ配線（`setTexture`とレイヤーの有効状態の相互反映）で実装できる。Datamoshが固定段からレイヤーへ移った前例と同じ経緯である。
- 既定順を最後にすると、旧来の「Main Stackの後」と同じ見た目が既定で保たれる。
- 高さ場を単一の入力にすれば、手続き型と画像が同じ照明計算を共有でき、新しい素材はheight関数の追加だけで済む。
- グローバル座標で評価すると、既存のSeamlessのようにタイル結合後に後処理を掛ける必要がなく、GPUだけでタイル書き出しと一致する。検証ではタイル分割と単一タイルの差が最大1（8bit）だった。
- 画像を保存しない規則は既存のImage Gradient／Overlay／Maskと同じで、Presetの移植性を保つ。

## 代替案

| 案 | 採用しなかった理由 |
| --- | --- |
| SANDBOXの固定段（Main Stackの後・Prismの前）にする | 当初の実装。順序が固定で説明しやすく、`effectStack`の契約を広げないが、質感の上下に他の効果を重ねる構成ができず、利用者が他の効果と同じ位置操作を求めた。 |
| Surface段（Normalと同じ位置）にする | 以降のEffectが質感込みの画像を歪められる一方、ライティングが歪んだ後の画像に対して不自然になる。 |
| 画像を法線マップとして直接使う | 一般的な法線マップ素材は使えるが、輝度の高さマップや手続き型と別の入力形式が増える。今回は高さ場に統一し、法線マップ入力は後から追加できる。 |
| Three.jsの3D表示で質感を作る | Clothのように別contextとコピーが必要になり、Main Stack出力を入力にする本要求と噛み合わない。 |
| タイル結合後にCPUで質感を適用する | Seamlessの方式だが、画素ごとの照明計算をCPUで行うと大きな解像度で遅く、GPUの結果と一致しない。 |

## 結果

### 利点

- CD、ヘアライン、旋盤仕上げ、紙の質感を、同じ照明モデルの見た目パラメータだけで作れる。
- 素材の追加が高さ関数の追加で済み、画像も同じ経路を通る。
- Preview、Thumbnail、静止画、動画、タイル書き出しが同じshaderを使い、結果が一致する。

### 欠点・コスト

- 高さ場から画素ごとに3回の高さ評価が必要で、フル解像度で1パス分のコストが増える（実GPUでの時間は未測定）。
- Effect Stack V2だけで動く。Legacy V1のPresetはV2へ昇格して読み込まれるため実害は小さいが、V1を保持したままでは適用されない。
- 主スタックの種類が13になり、MCPの`EffectKind`にも`texture`が加わる。外部scenarioが種類の一覧を前提にしている場合は追随が必要になる。
- 質感より後ろのレイヤーは質感ごと画像を処理する。Glass、Distortなどの歪みを後ろに置くと光沢の向きが崩れることがある（利用者が順序で調整する）。
- SANDBOX時代の保存（レイヤーがなく`texture.enabled`だけが有効）は、読み込み時にレイヤーを有効にして引き継ぐ。
- 画像はPresetへ保存されないため、共有したPresetでは画像素材が手続き型プリセットへ戻る。
- 模様の周波数は固定の相対値で、プレビューの縮小表示ではモアレが見えることがある。

## 再検討条件

- 法線マップやラフネスマップなど、高さ以外の素材入力が必要になった場合。
- 画像素材をPresetへ含める保存形式（アーカイブ形式）が決まった場合。
- 実GPUでのフレーム時間がPreviewの目標を超えた場合。
