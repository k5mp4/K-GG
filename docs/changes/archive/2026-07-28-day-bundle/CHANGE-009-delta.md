# Delta

## ADDED Requirements

### DEV-001 変更パッケージの単位

観測可能な変更は、会話ターンごとではなく、Why／What／対象外／受け入れ条件がまとまった承認済み変更パッケージとして管理します。1パッケージにつきactive changeディレクトリを1つ作成します。

### DEV-002 追加指示の取り込み

実装中の追加指示が既存パッケージのWhy／What／受け入れ条件と同じ目的・影響範囲に収まる場合、既存changeへ追記して再検証します。目的、利用者影響、保存・出力契約、対象外、受け入れ条件のいずれかを変える場合は新しいchange候補として分離し、必要なら既存changeを再レビューへ戻します。

### DEV-003 コミットとGit操作

承認済み変更パッケージに属するコード、テスト、文書は、検証結果と意図的な差分確認後に同じコミットへまとめられる構造にします。コミット、push、Pull Requestなどの外部Git操作は、ユーザーが明示的に依頼した場合だけ実行します。複数コミットが必要な場合は、各コミットの目的をvalidationまたは開発ガイドへ記録します。

### DEV-004 文書の責務分離

`AGENTS.md`はエージェントが必ず守る短い境界条件を記載し、変更パッケージの詳細な状態遷移・artifact・レビュー基準は`docs/development/`の単一の開発運用ドキュメントへ集約します。current specはアプリの現在仕様、changeは今回の差分、Archiveは完了履歴として維持します。
