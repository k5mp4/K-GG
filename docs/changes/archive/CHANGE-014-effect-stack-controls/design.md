# Design

## 採用する実装方針

ランダム化で各レイヤーのパラメータを補間するのではなく、現在のEffect Pipelineによる出力と、ランダム化後のEffect Pipelineによる出力を同じ入力・同じフレーム時刻で一時的に生成し、画面上でブレンドする。これにより、順序変更による出力の不連続を抑えつつ、既存のレイヤー設定・時間依存エフェクトの意味を変更しない。レイヤー行は変更前インデックスとの差分をFLIP相当の一時`translateY`として適用し、現在位置から目標位置へ移動する。

ランダム化ボタンの押下時に目標順序を一度だけ決定する。遷移元の状態と目標状態を一時的に保持し、`easeInOut`で0から1へ進む進捗を描画フレームごとに更新する。進捗が1になった時点で目標順序を通常の`effectPipeline`へ確定し、一時状態を破棄する。遷移中のランダム化ボタンは無効化する。

## データモデル

Presetのデータモデルは変更しない。ランダム化後の主スタック順序は既存の`effectStack`へ保存する。遷移元、遷移先、進捗、開始時刻はReactまたは描画ブリッジの一時状態として保持し、シリアライズ対象にしない。

## 状態管理

ランダム化処理は、正規化済み9層から目標順序を作る純粋関数と、プレビュー遷移を開始・更新・完了する実行境界に分ける。順列生成の乱数はテストで注入できるようにする。ソロ化と通常の手動並べ替えは遷移を開始せず、既存の即時更新を維持する。ソロ化では主スタックの`enabled`値だけを一時スナップショットへ保持し、同じ対象の再Altクリックで復元する。通常のクリックまたはToggle変更が行われた場合はスナップショットを破棄する。

## UI構成

ランダム化ボタンは遷移中にdisabledとし、ツールチップで操作内容を示す。Effect Stackの各行は主スタックの並び替え時に`top`位置を400msの`ease-in-out`で遷移させ、キャンバスのクロスフェードと同時にレイヤー一覧も滑らかに移動する。Altクリックのソロ化は描画結果のクロスフェード対象に含めず即時更新とする。オンオフのToggleをAltクリックした場合も同じソロ処理へ入る。

## 描画・外部プロセス・Tauri側の変更

通常のプレビュー描画だけが遷移ブレンドを使用する。thumbnail、静止画、連番、動画exportは一時遷移状態に依存せず、確定済みのEffect Pipelineを使用する。export開始が遷移中の場合は、目標順序を確定してから既存のexport状態を開始する。描画の二重評価でGPU負荷が一時的に増えるため、遷移は400msの短時間に限定する。

## 変更対象の主要ファイル

コード:

- `src/components/PostprocessStackPanel.tsx`
- `src/lib/effectPipeline.ts`
- `src/hooks/useWebGL.ts`または既存のプレビュー描画ブリッジ（実装境界を確認して選択）
- `src/store/gradientStore.ts`（確定タイミングが必要な場合のみ）

テスト:

- `src/lib/effectPipeline.test.ts`
- 遷移進捗・イージングの純粋関数テスト（既存テストへ追記、または専用テストを追加）
- exportが一時遷移状態を保存・参照しないことの回帰テスト

## 代替案とトレードオフ

- レイヤーのパラメータを順序変更に合わせて補間する案は、異なる効果の意味が対応せず、意図しない見た目になるため採用しない。
- UIの行位置だけをアニメーションする案は、描画結果の突然の切り替えを解消しないため採用しない。
- 常に目標Pipelineだけを描画してCSS opacityで見せる案は、現在結果を保持できず、Effect Stackの描画結果を正しくブレンドできないため採用しない。

## 移行方法

保存形式の変更はない。既存Presetはそのまま読み込み、ランダム化操作を実行したときだけ一時遷移を経て新しい順序を保存する。

## ロールバック方法

ランダム化の遷移境界を無効化して、目標順序を即時に`effectStack`へ適用する旧実装へ戻せる。ソロ化、既存の手動並べ替え、保存データには影響しない。
